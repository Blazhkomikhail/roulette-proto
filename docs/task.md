# Тестове завдання: керівник ШІ-розробки (ігровий фронт)

## 1. Про завдання

Це завдання на керування ШІ: ви працюєте з агентом, а ми дивимося і на результат, і на те, як ви до
нього дійшли. Інструменти — будь-які із погодженого списку; список і витрати вкажіть у звіті.

## 2. Умови

- Строк: 5 календарних днів.
- Оплата: не оплачується. Наступний етап — окремо, для фіналістів.
- Результати належать замовнику, завдання конфіденційне.

## 3. Завдання A — стіл рулетки

Самостійний проєкт: `roulette-proto/`, Vite + TypeScript + Pixi.js v8. Порожній проєкт, власні
`package.json`, `tsconfig`, тести. Бекенду немає.

### Що зробити

1. **Стіл 0–36 і зовнішні зони**: номер (straight), спліт, стріт, корнер, лінія, колонка, дюжина,
   червоне/чорне, парне/непарне, 1–18/19–36. Сектори не потрібні: їхні списки чисел нам не передали.
   Геометрія будується з даних (конфіг столу), а не зі списку зі 150 координат.
2. **Фішки 1 / 5 / 10 / 25 / 100**: вибір номіналу, клік по зоні кладе фішку в слип, повторний клік
   додає, Shift+клік або правий клік прибирає одну. Стек фішок видно в зоні.
3. **Модель слипа — чистий TypeScript**, без Pixi: `addChip`, `removeChip`, `undo`, `clear`,
   `double`, `totalStakeMinor`, `toBets()`. Ставка: `{ type, numbers, amountMinor }`, суми — цілі
   minor units рядком.
4. **CLEAR / UNDO / DOUBLE** і ліміти прототипу: на номер не більше 100, сумарно не більше 1000.
   Перевищення — відмова з повідомленням, а не мовчазне обрізання.
5. **Підсвітка зони під курсором** і підказка з назвою ставки над столом.
6. **Юніт-тести на геометрію і модель**: кожна зона дає правильний тип і числа (корнер 32/33/35/36,
   спліт 0/1, лінія 1–6); нуль не входить у корнер, стріт і лінію; прямокутники не перекриваються;
   клік у центр і в точку на 1 px всередині краю дають одну зону, на межі номера і спліта виграє
   менша зона; `double` подвоює, `undo` повертає, `clear` обнуляє; ліміт спрацьовує на межі (100
   можна, 101 не можна).
7. **Скриншоти**: порожній стіл, стіл зі ставками, підсвітка зони.

### Що додати

- **Лог роботи зі ШІ**: постановки, ітерації, що модель зробила невірно і як ви це виявили.
- **Сирий вивід** `typecheck`, тестів і збірки — текстом, а не переказом.
- **Витрати**: скільки ітерацій, токенів і годин пішло.
- **Список того, що ШІ зробив неправильно**, і яка перевірка це виявила.

## 4. Завдання B — розбір діфа

Нижче — діф із чужого проєкту. Він збирається, тести проходять.

```diff
--- a/src/slip.ts
+++ b/src/slip.ts
@@ class Slip {
   private bets: Bet[] = [];
 
   add(bet: Bet): void {
     this.bets.push(bet);
   }
 
+  /** Подвоює всі ставки в слипі. */
+  double(): void {
+    for (const bet of this.bets) {
+      bet.amountMinor = String(parseFloat(bet.amountMinor) * 2);
+    }
+  }
+
+  totalStakeMinor(): number {
+    return this.bets.reduce((sum, bet) => sum + parseFloat(bet.amountMinor), 0);
+  }
 }
```

```diff
--- a/src/slip.test.ts
+++ b/src/slip.test.ts
@@ describe("Slip", () => {
+  it("подвоює ставку", () => {
+    const slip = new Slip();
+    slip.add({ type: "straight", numbers: [7], amountMinor: "10" });
+    slip.double();
+    expect(slip.totalStakeMinor()).toBe(20);
+  });
 });
```

Дайте письмову коротку відповідь:

1. Тести зелені — отже, все вірно? Відповідь обґрунтуйте.
2. Що зламається в експлуатації: назвіть конкретні сценарії.
3. Яка перевірка це виявить: тест, інваріант чи зміна типу. Потрібне формулювання, а не
   «більше тестів».
4. Чи є другий і третій дефект, окрім очевидного?

## 6. Критерії прийому

| Перевірка | Очікуваний результат |

| Лог роботи зі ШІ | доданий: постановки, ітерації, помилки моделі |
| Сирий вивід команд | є, а не переказ |
| Завдання A | працює; тести покривають крайні випадки й падають при поломці межі |
| Завдання B | названі дефекти і запропонована конкретна перевірка |
| Завдання C | відповіді конкретні, є щонайменше одна чесно неперевірена річ |

| Список помилок ШІ | є, з перевірками, які їх виявили |
